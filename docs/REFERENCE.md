# 鲸伴

当前版本：v1.75。左侧「关于」显示安装版本及历次更新记录。

## 连续消息与真实电脑玩闹（v1.75）

QQ收到同一联系人连续发来的文字、图片和表情，会在短暂输入间隔后合并理解并生成一轮回复，原始消息和图片仍分别保存。图片读取按原消息编号进行，不用后发的表情覆盖前面的截图。排队中的同一联系人消息会合并；尚未调用工具的旧生成可以取消后结合新内容重写，已启动的操作不会因此重放。

普通QQ闲聊可以对收尾、点头等消息选择不回复；明确的问题、任务和工作模式不走这一静默分支。短的普通回复即使带换行也尽量发成一个气泡，长说明、代码和列表继续保留结构。模型生成的取舍仍会受具体上下文影响。

“鲸鱼心跳 → 设置 → 观察与电脑操作”新增“允许她实际移动鼠标、挪动窗口来逗你”。开启后，普通聊天和自主心跳可根据当下情绪调用 `play_with_computer`：真正轻微扰动鼠标位置，或挪动当前普通窗口并申请放回。操作通过Windows接口执行，普通鼠标移动不会取消；实际点击、拖动、切换前台或工作模式会放开。按Esc、说“停／别闹”或使用托盘“停止电脑玩闹”会停止，并暂停本次会话中的后续玩闹；托盘“恢复电脑玩闹”或聊天“继续玩”可以恢复。每个动作会结束，不连续重启来拉长时间；不会锁住键鼠、注入点击、输入文字或关闭应用。

新安装默认不启用电脑玩闹，仍需电脑操作权限；本机按本次明确要求开启。已检查连续图片的实际工具上下文、可选沉默、旧回复替换、已启动工具不重放及完整界面启动；真实Win32窗口移动使用隐藏的测试窗口验证移动和恢复，鼠标扰动使用隔离输入驱动检查，未移动用户当前鼠标或操作正在工作的窗口。本次不生成安装包。

## 接话、表情与持续的QQ生活（v1.74）

普通模式更侧重理解当下语气，几字、一句、轻微互损或贴切的表情都可以完成一次闲聊，不强制凑字数。精简聊天工具保留收藏表情的查询和查看能力；真实发送成功后可以仅用图片回应，客户端历史保留图片及工具回执。QQ主动搭话也可选择一张真实收藏表情，不再只能生成纯文字。

心跳可用 `qq_plan_activity` 自己发起公开动态、检查留言、昵称签名、头像及在线状态的打理。打算持久保存并绑定当时登录的QQ；同项待办合并，执行前记录状态，中断且结果不明的动作不自动重做。公开正文仍由独立QQ回合生成，不把心跳的私聊、屏幕或私人反思直接交给发布流程。

QQ自主回合保留近期选择和未完想法，可参考有实际工具来源的公开页面线索，实际新见闻会唤起重新考虑。客户端正在普通聊天、输入文字不再使后台QQ管理无限等待；工作模式、安静时段和用户保存的关闭状态继续生效。“QQ接入 → 空间与资料”新增“她的QQ生活”，可查看最近想法、待办及连接状态，或点“让她现在想想”。新见闻唤醒不增加固定每日额度。

本版进行了隔离的真实工具流程检查、模拟QQ回执与完整界面启动检查，没有向真实QQ发送测试消息或修改真实账号资料。少量模型口吻样本仍有表达差异；短句、态度和选图由当前模型结合上下文生成，不用固定台词替换。没有增加依赖，不生成安装包。

## 挂件首次显示重影的进一步修正（v1.73）

v1.72的独立窗口处理未解决用户实际出现的重影，之前检查窗口句柄稳定不足以证明画面正常。本版在QApplication和首次WebEngine初始化之前，为内置网页挂件设置Qt Quick与Chromium的软件渲染路径；不更改Windows或外部浏览器设置。透明挂件的网页从首次响应开始就是透明背景，不再先输出介绍页面再等脚本隐藏；移除1像素初始裁剪，先完整初始化透明帧，再应用角色点击区域。

验证增加实际像素检查：确认使用GraphicsApi.Software、读取真实帧缓冲、检查原生窗口透明像素，并确认移动绘制内容后旧位置的像素清空。原插件菜单、拖动保存、桌面/主窗口切换继续检查。修改需从鲸伴托盘菜单完全退出后重新启动才能加载，关闭聊天窗口或仅重启插件无法重新选择渲染后端。本次不生成安装包。

## 挂件首次启动残影修复（v1.72）

“鲸伴主窗口”模式改为独立透明原生绘制层，通过原生窗口的临时归属跟随主窗口，不再把WebEngine放进主窗口的绘制树；跟随移动、缩放、最小化和隐藏，桌面模式仍独立显示。透明背景每次绘制显式替换旧帧，点击区域改变时刷新挂件层，避免首次启动时的重复人物、拼贴及黑块残影。

对比验证中，旧实现首次加载会将主窗口从RasterSurface切为Direct3DSurface并更换原生窗口句柄；修复后普通冷启动、隐藏启动后显示时的主窗口句柄及绘制类型保持不变，原插件菜单、拖动、位置保存及显示位置切换通过检查。验证使用隔离插件状态及模拟余额。本次仅更新程序与联网更新目录，不生成安装包。

## 主窗口与桌面挂件（v1.71）

`dsh-whale-widget` 使用透明原生挂件宿主。到“插件 → DSH插件兼容”，在该插件卡片的“挂件显示位置”选择“鲸伴主窗口”“桌面悬浮”或“暂时隐藏”。默认贴在主窗口里；桌面模式是独立置顶透明窗口，主窗口最小化或驻留托盘时仍会显示。空白区域鼠标穿透，角色可以拖动，主窗口和桌面分别记住位置。点击角色或原菜单按钮继续使用原插件菜单和余额面板；点“显示挂件”可恢复隐藏，点“重新加载挂件”可刷新。

保留插件原始代码和资源，通过原有本机接口加载；不新增Electron或npm依赖，不额外调用模型。停用插件或退出鲸伴会关闭挂件。已验证原插件在隔离配置与模拟余额下的挂载、透明渲染、点击区域、拖动保存、菜单、隐藏恢复和窗口缩放；系统窗口截图接口超时，未完成该接口的桌面截图核对。

## QQ图片读取修复（v1.70）

修复QQ临时图片链接返回HTTP 400时直接失败、遗漏本机原图缓存的问题。现在优先通过OneBot取得原图，独立尝试Base64、本机桥接确认的缓存及图片链接；某个来源失效或无法解码会继续尝试其他来源。支持按实际位图内容识别无常规后缀的QQ缓存文件，保留大小与像素限制；只信任本机桥接返回的缓存位置，不读取聊天消息直接指定的本地路径。失败诊断写入 `.updates/diagnostics/qq-images.log`，只记错误类别与HTTP状态，不写临时签名链接或凭据。

## 已有登录、自主选片与安装包（v1.69）

评论默认沿用已登录的日常浏览器，不再悄悄转去另一个未登录的独立会话。“鲸鱼心跳 → 浏览与活动”点“接入已登录的浏览器”，在原来登录B站的同一个 Edge/Chrome 资料里加载打开目录中的连接扩展；已有扩展在扩展管理页重新加载即可。首次需要这一步，随后保持该浏览器开启就会自动连接，不用再次登录B站。扩展新版可直接后台读取/提交评论和点赞，不打开视频页；旧扩展仍兼容后台标签页方式。登录Cookie及校验值留在扩展内部，不返回软件。验证码、结果不明与重复提交保护继续生效。

首次升至本版会把观看通道切到日常浏览器，已保存的功能关闭状态保持不变。固定选题偏好已移出设置，旧关键词不再传给选片模型。她依据持续兴趣、心情和真实见闻自行选择，可以先逛首页推荐再判断候选，不再强制先凑搜索词；你在当前对话明确指定的观看内容仍会被考虑。

双击项目根目录的 `生成安装包.bat`，会先生成不含个人数据的纯净目录，再生成 `I:\鲸伴发行\鲸伴-v1.69-安装包.exe`。本机已备好 Inno Setup 7 编译器；换到其他制作电脑时需安装 Inno Setup 7，或通过 `--compiler` 指定 `ISCC.exe`。接收者只需安装包，不需要编译器或系统Python。安装包包含Python、应用依赖和OneBot运行组件，可选本地语音大模型仍按需下载。

默认安装到当前用户的 `%LOCALAPPDATA%\Programs\JingBan`，提供桌面/开始菜单快捷方式和Windows卸载入口。覆盖安装保留个人配置；卸载保留运行期间产生的聊天、附件、登录资料及用户插件，不清空整个目录。已有便携版可选择原目录安装；迁到新目录时请用软件的数据迁移功能。安装包不会携带开发者的数据库、密钥或登录状态，也不会默认开启开机自启动。

## 后台浏览、评论与精简设置（v1.68）

“鲸鱼心跳 → 浏览与活动”是独立浏览入口，QQ接入里不再放B站设置。浏览能力、B站互动在本版首次升级和新安装时默认开启；保存关闭后会尊重你的选择。QQ接入精简为连接登录、聊天与联系人、空间与资料、运行记录四页，详细选项折叠显示。

B站的读取评论、发表评论、点赞/取消点赞改用后台登录会话和实际接口，不再依赖视频页面的评论编辑框。v1.69起默认接入已有登录的日常浏览器，不再以独立会话登录为主要流程。后台提交不会弹出或切换浏览器。站点要求验证码时会停止提交，操作结果不明时会留下记录并禁止自动重发。

新增 `browse_webpage`，可在后台真正渲染普通公开网页并读取正文、链接，覆盖新闻、论坛、文档等网站，不限B站。复杂应用操作沿用电脑操作总开关；角色可以管理语音、思考、观察、自主偏好、浏览互动、分享和QQ自主资料等日常设置。长期打算与实际见闻继续保存在本机，是否行动、是否分享和下次何时继续分别决定。

普通模式先以20至60字的一两句接话为目标；过长的日常最终回复会额外进行一次不带工具的短编辑，并重新检查工具事实，编辑失败则保留原文。工作模式、代码及明确要求详细解释的内容不压缩。实际模型用量计入总用量，原始推理不会提供给短编辑。角色思考演绎改为一句、目标不超过40字。

`dsh-whale-widget` 的网页宿主增加原插件要求的聊天挂载标记，启用后自动打开挂件界面，显示挂载状态并提供重新加载；后台托盘启动仍可手动打开。保留原插件界面与代码。它是网页挂件，与 `dsh-pet` 的透明桌面窗口是两个插件。

浏览器登录资料不进入纯净发行目录或聊天迁移包。自主行为拆分参考了作者的 [主动搭话](https://github.com/Yuuyuko-uu/dsh-speak-up)、[观看与表达分开](https://github.com/Yuuyuko-uu/dsh-bili-subagent) 实现说明；本版沿用鲸伴自己的模型、记忆与执行记录。

## 对话分流与自由安排（v1.67）

- 普通、工作模式分别保存聊天和输入草稿，近期上下文独立；原有聊天保留在普通模式。长期记忆、事件记忆和主动历史查询继续共享。QQ仍使用原有身份隔离，本人QQ需自己绑定。
- 回复或附件尚在处理时先完成再切换；通过聊天要求切换模式时，在当前回复及排队任务结束后切换。
- 设置页支持纵向滚动，输入框保持正常高度，小窗口下表单会换行。
- 鲸鱼心跳按兴趣、持续打算和实际进展选择研究、创作、浏览网页、操作应用或休息；观看B站是可选活动之一。电脑动作沿用聊天栏总开关和批准方式。
- QQ自主互动由模型选择活动及下次考虑时间，不再使用旧的每日条数、发布间隔和每人主动间隔。旧的频率字段仅兼容存档，不作为自由安排的配额。
- QQ接入的「自主与权限」增加「由她自己决定何时换昵称、签名和头像」。升级时，原先同时允许AI管理资料和自主发动态的配置会启用此项；关闭即可停止自主资料变更。总资料权限关闭时不执行。
- 动态和头像记录图片文件及画面指纹，近期用过的配图不再作为自主候选。旧版本未记录图片指纹的历史发布无法准确追溯，指纹从本版开始累积。
- 空间读取兼容接口实际返回的JavaScript数据字面量，不执行返回脚本；本人动态使用本人流，不再把本人QQ填入好友筛选。只回复本次实际读到、重新核对过的评论，结果不明不重复发送。

空间参数与数据结构核对参考：[onebot-qzone读取流程](https://github.com/Gu-Heping/onebot-qzone/blob/main/doc/获取说说流程说明.md)。不同账号可见范围和服务端验证可能影响可读内容。

版本号由 `version.json` 管理，日志保存在 `CHANGELOG.txt`；发布新版本时同步更新这两个文件。发布归档目录为 `I:\鲸伴更新`，按版本分别保存更新说明和程序源码。早期版本只有用户提供的日志，v1.16 起保存程序快照。联网更新使用「网站上传/jingban」目录中的签名清单和静态发布文件。

设置中的「启用思考」按模式生效：普通模式配合「普通模式显示思考演绎」，显示短的角色独白，标题为「思考」，旁边标注「角色演绎」；普通模式向接口关闭原始推理，不显示或保存新回复的原始推理。工作模式按「启用思考」开关生成并保留真正的模型原始思考，工具续轮仍遵守原文回传协议。切换到普通模式会隐藏界面中已有的原始思考区域；既有数据库记录不批量删除。左下角「记忆状态」可点击进入长期记忆页。

思考演绎优先随同一次最终回复创作，缺失、重复正文或仍是提纲时，最多额外进行一次不带工具的短请求补充；客户端与QQ使用相同设置。补生成只提供角色语气摘要、少量对话文字和已接受的正文，不提供原始推理或图片；补生成期间客户端先显示正文。演绎与正常回复分开保存，不进入历史事实检索、长期记忆提取、语音或QQ正文。界面显示补生成中或失败原因，不用固定台词填充。

普通闲聊保留角色、最近消息、记忆检索、引用与表情等基本能力，操作类工具定义和长执行说明按需加载；模型可调用load_action_tools取回当次已授权的完整能力，不靠固定关键词开放功能，不扩大权限。明确任务、历史原图/开头查询、实时观察、工作模式和自主活动继续使用完整执行说明；已有相关历史/事件候选保留，证据检查和取消规则继续生效。需要实际操作的复杂往返仍可能使用较多Token。

右上角用量是本机累计，不是单句回复长度：输入包括角色、历史、资料和工具定义，多轮调用会重复计入上下文；累计还包含记忆整理、主动决策等后台请求。用量窗口显示今日对话/记忆整理/自主活动及其他的分类，以及最近一次对话的输入、输出与合计（含工具往返及演绎补充）。缓存命中属于输入的一部分，不另加一遍。优化后的实际用量以接口返回统计为准，没有固定下降比例；后台开关和运行频率沿用原设置。

## 从 DSH 迁移聊天记录（v1.66）

入口：设置 →「数据迁移 · 备份 / 导入 DSH 聊天」→「从 DSH 迁移聊天记录」。

1. 直接迁移：先退出 DSH，选择其 `sessions` 文件夹。默认通常在 `%USERPROFILE%\.dsh\sessions`；配置过 `DSH_HOME` 则选择相应目录。扫描子目录并优先读取最高版本的日志，支持 `.jsonl`、`.jsonl.zstd` 和 `.jsonl.zst`。压缩日志复用已安装的 DSH 兼容共享 Node 运行环境，不启动插件；没有环境时可选择下面的 ZIP 方式。
2. 日志包迁移：在 DSH 目标会话顶部「更多」→「下载 Session 日志」，或输入 `/export` 下载 ZIP，再在鲸伴选择该文件。[DSH 官方导出说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/session-query/session-log-export/README.zh.md)说明了入口和包内日志、附件结构。还接受含 `header/session + events` 或 `messages` 的结构化 JSON；不把任意 Markdown/PDF 当成无损聊天导入。
3. 预览标题、条数、时间和部分原文，勾选需要的会话；子代理会话默认不勾选。点击「导入所选会话」。追加前自动保存 `backups/before-dsh-import-*.sqlite3` 数据库快照，写入采用一个事务，失败回滚并清理本次新附件副本。不会自动迁移 DSH 的密钥、插件设置、原始推理或工具执行状态。

导入保留用户/助手正文及原消息时间；缺失时间明确标为未知。只导入追加的聊天消息，过滤系统注入、目标续跑和压缩替换内容；同一会话的原消息按 ID/序号去重，不按文本去重，连续发送的“6”“1”也会保留。再次导入新增消息会追加，已有同 ID 内容不同的记录保留并报告冲突。ZIP 中引用的原图片和文件复制进鲸伴附件目录；没有原文件的消息保留占位并提示数量，不访问旧电脑路径或自动下载链接。复制压缩日志时逐帧解压，不只读取首帧头部。

默认导入记录只在历史记录里查看，可按正文或会话标题检索；聊天中可以请 AI 查找 DSH 旧对话、读取和引用原消息。导入记录不混入最近聊天上下文，本机用户及已明确绑定的本人 QQ 可检索，其他 QQ 会话不能读取这些历史。导入本身不调用模型，默认也不加入记忆方案整理；勾选允许整理后，后续按已有记忆方案设置处理并产生 API 用量。聊天列表展示有独立勾选项，之后也可在历史记录恢复/隐藏。

仅完成源码语法检查和格式源码核对，尚无用户提供的 DSH 导出样本，未在真实 DSH 记录上执行导入或进行界面联调。源格式与预览不匹配时会显示失败原因，不自动改动鲸伴数据。旧原生桌宠示例替换为「快捷短语」，原版 DSH 桌宠的兼容入口和用户设置保留。

## QQ回复与空间读取诊断（v1.65）

若聊天出现“Thinking mode does not support this tool_choice”，这是接口参数组合冲突。[DeepSeek接口文档](https://api-docs.deepseek.com/api/create-chat-completion/)明确不支持在思考模式强制指定工具。本版普通请求不显式传auto，指定工具的单次请求关闭思考；兼容接口仍返回对应400时，只将被拒绝、尚未生成或执行的请求改为默认选择加单一目标工具再请求一次。已发生的QQ、评论或电脑操作不因该兼容处理重放，工具续轮仍保留原始推理字段。

授权的QQ会话在模型请求失败或缺少API配置时收到简短状态提示，不将密钥、SDK原始错误或内部资料发到QQ。桥接意外断线后按1至30秒退避重连，手动断开和退出会停止；明确401/403认证拒绝停止重试。重连不自动重发未确认的发送或操作，也不保证补齐断线期间未送达客户端的消息。私聊按消息编号做有界去重，单条格式异常不关闭整条连接。

空间读取兼容JSON/JSONP、分号/注释/空catch包装、UTF-8或旧编码以及双引号字符串中的JS十六进制转义，只解析数据，不执行脚本。不把登录验证网页、业务拒绝、列表结构变化和模型决策JSON错误混为一谈。格式或验证错误在同次对话中不重复请求相同参数；当前只处理接口实际返回的近期可见动态和评论，不能绕过登录或可见范围限制，也不保证读到所有评论。

诊断文件为 `data/onebot/qzone-diagnostics.jsonl`，记录软件版本、时间、阶段码、异常类型、大小或解析位置等元数据，不写Cookie、接口正文、私聊或评论内容。读取失败不会伪造评论或发送回复；提交结果不明继续保留待核对状态，不自动重发。模型自主动态/回复决策可接受完整JSON代码围栏，截断或缺少布尔开关时明确报错，未通过校验的内容不发布。

本机完成源码语法检查，未登录另一台电脑或进行实际QQ收发、空间读写、模型请求联调。另一台电脑需要取得并重启到新版本；只修改开发目录不会自动修复其他电脑，联网升级需先上传本地生成的签名更新文件。

## 生成纯净发行目录

开发者双击项目中的 `生成纯净发行版.bat`。脚本将程序、公开角色素材、Python 本体、`.app-venv`、FFmpeg 和 OneBot 复制到项目旁边的 `鲸伴发行/鲸伴-v版本-纯净版-日期时间/`。每次新建目录，不覆盖已有发行，也不修改开发目录里的个人数据。

只把新生成的目录整体压缩后发给首次安装的用户。目录内的 `首次使用.txt` 说明启动和配置方式；接收者双击 start.bat 或鲸伴.exe，首次启动新建个人配置和聊天数据库，在设置中填写自己的密钥。

此流程不读取或复制现有 config.json、app_settings.json、data、downloads、plugins、plugin_data、plugins.json、.updates、缓存、个人表情和参考音频；公开外观及配置示例从程序源代码的默认常量重新生成。用户插件与个人角色状态不进入发行，程序的默认大肥鱼角色与头像保留。发行目录附带相对路径和 SHA-256 文件清单。

默认提供可直接运行的聊天、在线语音和 OneBot 环境，本地 Qwen 可按需安装。若项目已经完整安装本地 Qwen 环境和模型，可在项目终端运行 `生成纯净发行版.bat --include-local-tts`，将它们一同带走；未安装完整时会明确报错。公开文件清单位于 build_clean_release.py，新增本地程序模块时应一同维护。

## 生成联网更新

开发者双击项目中的 `生成联网更新.bat`，或使用 `鲸伴更新/生成联网更新.bat`。运行前先保存代码，修改 version.json 和 CHANGELOG.txt；如只修同版本内容，也能生成新的 build 清单。脚本先重新打包启动器，再生成签名发布文件、OneBot 组件、当前版本快照与版本索引，默认写到项目旁边的 `鲸伴更新`。

脚本只准备本机发布文件。上传时把 `鲸伴更新/网站上传/jingban/components` 和 `releases` 中的新增内容先放到网站 `/jingban/` 对应目录，全部完成后最后替换 latest.json。老版本的 releases 和 components 要保留。签名密钥、整个项目、个人配置与数据库均不上传。

纯净发行目录用于首次安装；联网更新目录用于已有客户端升级。联网更新包不包含 Python 环境和个人设置，不能拿来代替首次安装目录。生成纯净目录不需要签名私钥；生成联网更新沿用 `鲸伴更新/签名密钥/release-signing-key.xml`，不能更换成随机新密钥，否则旧客户端无法信任。

## 联网更新与文件修复

更新地址固定为 `https://api.xueluosh.top/jingban/latest.json`。启动器在后台下载并验证 RSA/SHA-256 签名清单，逐个比较受管理文件的大小和 SHA-256；版本相同也检查文件缺失、大小异常及内容不符，按文件补齐。文件未变化时不下载。新版本不依赖客户端必须安装过某个中间版本。

受管理范围包括程序 Python/UI/启动脚本、版本与日志、需求清单、官方界面素材、`鲸伴.exe` 和 `onebot/runtime` 的内置桥接程序。配置、数据库、对话附件、下载文件、用户角色资料、模型、Python 的 runtime、虚拟环境均不覆盖、不删除；不自动安装 Python 依赖。如果后者损坏，需恢复运行环境。`.updates` 是本地校验清单、下载缓存、暂存和备份目录，不在更新替换范围内。

下载全部完成并逐个校验后，启动器调用独立更新助手，退出自身，再备份原文件、按清单替换、整体验证，最后记录成功。版本文件最后替换。已下载文件可用于离线修复；缓存不全时仍需联网。替换失败恢复旧文件；断电留下的事务在下次启动时先恢复。聊天窗口的运行标记与更新锁防止新版客户端运行期间替换代码；更新前请退出仍使用旧版、尚未带运行标记的聊天窗口。网络不可用时保留本地文件并尝试原程序启动。

`start.bat` 仍优先显示外置启动界面；启动源码、界面模块、更新模块缺失，或源码启动失败时，转入自带运行库的 EXE 修复入口。EXE 中嵌入更新引擎、公钥、启动布局和官方图片，因此能在部分外置源码损坏时检查修复。至少需要保留一个可运行的启动入口；两者都被删除时需重新取得启动器。EXE 更新通过复制到暂存目录的独立助手完成，同时等待 PyInstaller 主进程及其引导进程退出。

左侧「关于」的「退出并检查修复」会先按现有关闭流程结束聊天/语音等任务，再重新打开启动器。常规启动自动检查，不在聊天过程中直接替换文件。

### 发布到静态服务器

打包配置会隔离 DLL 搜索路径，避免从其他 PDF/图像工具目录收集同名 ICU、UCRT 或 Windows API DLL。当前 Qt 使用 Windows 自带的 ICU 接口；构建时检查所需导出符号，不把不兼容的第三方 ICU 放进 EXE。发布工具同时记录本机已生成的签名清单，防止服务器尚未更新时用旧指针覆盖刚生成的修复文件。

1. 当前版为 v1.31；发布时同步修改 `version.json` 和 `CHANGELOG.txt`。即使不改版本号，新的文件内容也可通过新的 build 清单发布并修复到客户端；不以版本号作为唯一依据。
2. 运行 `build_launcher.bat` 重新打包修复启动器。启动器源码变动时必须重打包，保证缺失源码时的修复入口同步。
3. 使用项目 Python 运行 `publish_update.py`（默认输出到 `I:\鲸伴更新\网站上传\jingban`）。签名私钥默认从 `I:\鲸伴更新\签名密钥\release-signing-key.xml` 读取；私钥不在程序、更新目录或 EXE 中。
4. 只上传「网站上传」下的 `jingban` 文件夹至站点根目录。先上传 `components` 新压缩包和完整的 `releases` 新目录，保留旧版本目录；最后原子替换 `latest.json`。该清单应直接返回 JSON，建议 no-cache；带内容摘要的 release 文件可长期缓存。
5. 客户端固定信任内置公钥，清单校验失败或文件哈希不符时拒绝替换。签名私钥务必备份，不上传网站；后续发布沿用同一私钥。清单含 build 编号，客户端优先采用已验证的较新清单，避免缓存较旧指针导致回退。

旧的「源码快照」仅供归档，不作为联网更新格式。发布工具重新从当前程序目录收集受管理文件，生成签名清单和不可变的版本目录，不读取用户密钥、数据库或运行环境。

## 运行聊天程序

第一次使用先双击 `setup_app.bat` 安装聊天界面依赖，然后双击 `start.bat`。启动页会展示大肥鱼形象和启动进度；聊天程序准备好后自动关闭。运行时使用 `.app-venv`，不会调用系统 Python。

如需单独打包启动器，运行 `build_launcher.bat`，会在项目目录生成 `鲸伴.exe`。`start.bat` 优先运行外置 launcher.py，便于修改后直接生效；直接双击鲸伴.exe 使用打包时的版本。它包含启动界面、必要的界面运行库和角色图片，需与 `main.py` 和 `.app-venv` 放在同一项目目录；聊天程序、配置、数据库和语音文件都保持外置，不会被打包进去。

普通模式的思考区显示角色演绎，不启用原始推理；工作模式可在「设置」开启模型深度思考。附件读取、上下文整理和接口调用放在后台线程；收到的正文每 40 毫秒合并刷新，避免每个小片段都触发布局和滚动。需要解析演绎标记时先收齐正文再显示，防止标记进入语音或QQ。

聊天消息会实时追加到同一个气泡中；消息、长期记忆和 QQ 私聊记录保存在本机数据库。长期记忆候选需在记忆页由你确认后，才会放进之后的模型上下文。

聊天区支持图片、视频、PDF、DOCX 和常见文本文件附件。图片与视频分析使用 DeepSeek 的 `deepseek-flash` 视觉输入；视频会在本机用 FFmpeg 抽取最多 12 张带时间点的画面，B 站链接通过 yt-dlp 获取视频后使用相同流程。项目 tools/ffmpeg/bin 已包含 FFmpeg/ffprobe，也可使用系统 PATH 中的版本；B 站视频下载受网络、地区和平台访问限制。视频分析只理解抽取到的画面，不包含语音转写。PDF/Word/文本文件在本机提取文字后发送，扫描版 PDF 暂不支持 OCR。顶部「用量」面板累计 API 返回的实际 Token 统计，并通过 DeepSeek 官方余额接口在线查询账户余额。

## 自定义标题、头像和配色

用记事本或 VS Code 打开 `app_settings.json`。常改的内容：

- `window.title`：软件窗口标题；`window.icon`：图标文件路径。
- `brand.name`、`brand.mark`：左侧应用名和小标记。

图标和头像路径可写成项目内相对路径，例如 `assets/app.ico` 或 `assets/assistant.png`。改好后保存并重启软件。颜色使用 `#RRGGBB` 格式；如果写错，程序会自动使用默认颜色。

在「设置 → 会话与记忆 · 导出 / 导入备份」管理迁移文件。导出 ZIP 包含 `data` 下的全部数据库、长期记忆、附件、历史语音，以及 `assets` 和外观配置；额外提供 `memories.json` 方便查看。SQLite 数据库通过快照备份，不直接复制正在写入的文件。

应用图标与弹窗插图使用 `assets/mascot_v2.png`，由内置 image_gen 参考三张蓝发角色图重新生成，完整提示词记录于 `assets/mascot_v2.prompt.txt`。可修改 `app_settings.json` 的 `window.icon`、`dialogs.image`；也可以分别指定 `dialogs.info_image`、`dialogs.warning_image`、`dialogs.success_image`。聊天头像保持独立设置。

## 语音合成方式

语音页可选择豆包在线流式合成或本地 Qwen。豆包通过火山引擎 V3 SSE 接口逐块接收 PCM 音频，聊天回复会边生成边播放，并保存 WAV 文件供回放。豆包 API Key、资源 ID、音色 ID、用户标识和语速可在界面设置；API Key 保存在本机的 `config.json`。在线合成会按火山引擎账号的服务规则计费。

切换合成方式只切换设置页面，点击「保存语音设置」后才应用。常用配置直接显示，资源 ID、用户标识及本地推理参数收在「高级参数」中。修改设置后点击试听，也会先保存当前设置。豆包密钥已填写不代表服务已开通；需在控制台自行开通相应服务后才能合成。

本地 Qwen 使用独立的 Python 3.12 虚拟环境和 CUDA 版 PyTorch，不会安装到系统 Python。选择本地、启动应用或发送聊天均不会自动下载安装。只有点击「安装本地语音」并确认空间及下载说明，才会开始配置。可点击「取消安装」，保留已下载文件以便重试。安装完成后填写参考音频和文字，保存设置，再点击「启动本地服务」。参考音频保存在 `assets/voices/`，聊天记录和生成的回放音频保存在 `data/`。

本地语音页的「删除本地环境」会先确认，再移除 `.qwen-venv`、Qwen 模型、专用缓存及本地推理代码，完整环境约 7–10 GB。聊天数据库、应用虚拟环境、参考音频和历史回放音频会保留。需要恢复时重新点击「安装本地语音」并确认。首次设置或重建需要联网下载 Python 包和模型。

本地语音可调整语言、设备、计算精度、每段字数、随机度、Top P、Top K、重复惩罚和最大生成长度。参考音频及其准确文字只用于本地 Qwen 的声音克隆；豆包使用火山引擎音色 ID。

## 电脑操作 Agent

针对常见电脑操作话题，回复正文会先缓存到本轮工具调用决策结束；调用工具时的过渡话语不展示，只显示过程卡。模型未获得本轮成功命令结果却声称完成时，会拦截并要求纠正一次，否则显示未完成。该检查是有限的关键词保护，不等同于对任意电脑状态的验证；命令退出成功也不保证目标应用已完成任务。普通非操作聊天仍直接流式显示。

每次命令执行会在回复气泡中显示可展开的过程卡，包含目的、目录、完整命令、运行输出、耗时、退出码及取消/失败状态。运行中约每 0.3 秒更新一次输出；实际输出时机取决于被执行程序是否缓冲。输出最多显示末尾 16 KB。操作卡片保存在数据库独立的 command_traces 表，重启后可恢复，也随备份迁移。普通历史搜索和记忆提取不读取该表；追问或继续近期工具任务时，恢复最近相关命令的有界摘录。清理聊天显示时保留日志，彻底删除关联消息时一同删除。命令结果会发送给模型，用于完成当前任务。布局文件为 `command_trace.ui`，展示逻辑为 `command_trace.py`。

聊天栏勾选“电脑操作”后，本机聊天模型可运行 PowerShell、读取当前屏幕，或按真实截图点击、滚动、输入与按快捷键。在“电脑操作”菜单中选择逐次确认或自动批准；已保存的自动批准在重启后恢复。QQ 电脑操作使用“QQ 接入 → 信任与权限”的设置。关闭电脑操作会阻止后续操作，正在执行的命令会尝试停止；已发生的修改不会撤销。桌面输入需先观察，使用截图像素坐标，每次输入后提供新截图核实；窗口改变或截图超过30秒需重新观察。截图能否读取取决于当前模型的视觉能力与桌面状态。

命令在后台运行，最长 60 秒，返回最多末尾 16 KB 输出给模型；超时尝试停止进程树，不代表撤销已经发生的操作。这不是权限沙箱，执行权限等同当前应用用户，不应批准不理解的命令。AI 可能需要多次命令完成任务，逐次确认模式下每次独立确认，自动批准模式下直接执行。确认窗口源文件为 `command_approval.ui`，逻辑为 `command_agent.py`。

发送消息时重新启用自动跟随，聊天区域高度变化后继续滚到底部；向上滚动或拖动滚动条会停止自动跟随。

## QQ 接入与内置 OneBot（v1.31）

项目内置官方 NapCat v4.18.41，位于 `onebot/runtime`，仍需本机安装兼容的 Windows QQ。打开“QQ 接入”，点击“启动并登录 QQ”，启动日志和登录二维码会直接显示在页面中，不另开命令行窗口。使用手机 QQ 扫码并确认后，默认自动连接鲸伴。若无法检测 QQ，可手动选择 QQ.exe；管理端口默认 6099，WebSocket 地址默认 ws://127.0.0.1:3001，两个端口只供本机使用，且不能相同。已有旧版 NapCat 运行时需先退出旧实例，否则会提示端口占用；也可直接用原来的连接按钮接入已有外部桥接。

“随鲸伴启动内置服务”默认关闭，勾选后请保存 QQ 设置。自动回复、白名单、语音和表情开关沿用现有设置，新安装默认不自动回复。“停止服务”结束鲸伴此次启动的桥接进程树；退出鲸伴也会停止内置服务，不会批量结束其他 QQ 进程。“断开桥接”仅断开鲸伴的 OneBot 连接，不停止服务。

原控制台输出由加载入口转存到 `data/onebot/console-current.log`，上一轮保留为 `console-previous.log`，界面最多显示 2000 行并隐藏访问令牌。二维码来自本机 `data/onebot/cache/qrcode.png`；刷新二维码、登录阶段和在线状态使用本机管理接口。手机确认、额外风控和身份验证需用户自行完成。不会通过这里自动发送测试消息。

NapCat 的配置与缓存保存在 `data/onebot`，更新只分发 `onebot/runtime` 中的程序文件。签名更新清单的可选 `components` 字段记录 OneBot 压缩包及每个程序文件的摘要；客户端先验证压缩包和文件，再暂存、备份、替换。同版本也能修复组件。v1.21 等旧客户端先安装新启动器，新启动器重启后读取已签名的本机清单并完成组件下载；直接运行 main.py 跳过启动器时，如果组件缺失，可在 QQ 接入点“退出并修复组件”。上传服务器时先上传 `jingban/components` 与新增 `jingban/releases`，最后替换 `latest.json`。

NapCat 来源：[官方发布 v4.18.41](https://github.com/NapNeko/NapCatQQ/releases/tag/v4.18.41)，安装说明：[官方 Shell 文档](https://napneko.github.io/guide/boot/Shell)。原始发行包摘要与来源保存在 `onebot/runtime/jingban-release.json`，上游许可证保存在同目录 LICENSE。鲸伴不修改上游程序，整合用的加载入口在本机数据目录生成。

### QQ 图片与语音

QQ 接入页分为连接、自动回复和手动发送。手动输入接收方 QQ 号，选择图片/GIF 或语音文件即可发送；自动回复沿用白名单，并分别提供表情和语音开关，修改后保存 QQ 设置。两个开关表示允许 AI 自主选择，不是每条都发送。自动表情使用本地表情库，语音使用已保存的语音配置。在 QQ 中说“用语音回答”，模型可选择将本次回复合成为完整语音发送，不额外发送重复文字；也可根据语境主动选择语音或表情。语音合成失败时尝试改发文字，桥接发送失败仍通过状态提示反馈。QQ 语音保存到本机，可从同步的回复回放；不在电脑上同时自动播放。

发送使用 OneBot 11 的 text/image/record 消息段。媒体在后台编码传输，单文件最多 30 MB；等待桥接成功回执后才显示已发送，超时或拒绝会提示，超时不会自动重发。语音格式转换取决于桥接实现。

“清理”只是隐藏聊天列表中的消息，不删除数据库原文、附件、语音、记忆或引用，不释放磁盘空间；AI 仍可检索、记忆和引用这些消息。可在“已清理”中恢复。主聊天界面仍只加载最近 300 条未清理消息。显示状态随现有数据库备份迁移。原消息旁的“删除”仍是彻底删除并清除相关自动记忆的操作，与此功能不同。

管理窗口布局为 `history_manager.ui`，可用 Qt Designer 修改，再转换为 `ui_history_manager.py`；操作逻辑在 `history_manager.py`。

Token 优化：保留最近 24 条消息与现有长期记忆，精简默认人设及引用规则；已经在上下文中的被引用原话不再重复发送。普通“今天……”话题不再自动附上当天全部记录。模型检索先取得最多 6 条短摘要，需要细节时分页读取原文与文档，数据库内容不裁剪。

主动引用：每轮在本地预检索最多 3 条相关旧消息候选，模型判断关联后选择引用。引用标记在流式处理中转换为卡片，显示和语音只接收正文，单纯引用无需额外模型请求。预检索是文字匹配，不保证找到所有语义相关的经历；模型仍可主动换词搜索。较长历史、附件或多轮检索仍会增加 token，用量以实际 API 统计为准。

电脑聊天现在可以让 AI 调用历史搜索，再引用数据库中的原消息。可以说“找一下我之前说的关于搬家的那句话，引用给我”或“之前那张头像图帮我找一下”。引用卡可点击查看完整原文和图片，并定位到已加载的消息；超过界面加载范围的旧消息也可独立查看。原消息删除后，引用卡显示已删除。

搜索使用文字关键词及中文片段匹配，由模型选择和改写检索词，不是图片视觉搜索。旧图目前按随附文字和文件名查找；只有图片、没有可描述文字时，可能需要进一步确认。搜索和选取引用会增加 API 请求与 token 用量，普通回复仍按流式显示。

输入框旁的“表情库”支持导入 PNG/JPG/WebP/GIF、改名和删除。建议使用“开心”“无语”“晚安”等含义清晰的名称；AI 会从已导入的表情里选择，最多每次回复一张。GIF 支持动画显示。文件位于 `assets/stickers`，无需在线表情服务。删除表情会使旧消息中的对应表情不可用。现有会话迁移备份会包含表情文件与引用关系。

本功能目前用于电脑聊天；QQ 仍沿用文字回复。界面源文件保留在 `chat_window.ui`，由其生成 `ui_chat_window.py`；检索逻辑位于 `chat_tools.py`，卡片和表情库窗口位于 `message_cards.py`。


聊天输入栏统一为“附件 / 表情 / 语音回复 / 电脑操作”，电脑操作开关及自动批准选项收在下拉菜单；除发送按钮外使用统一的中性色，启用状态用浅色底显示。

## 新风格起点

风格起点改为数据库内、按会话保存的 `context_settings`，同时校验对应消息的时间与内容摘要；旧的 `assets/character/style_profile.json` 中裸 `history_after_id` 不再用于过滤上下文，也不自动迁移，避免删除数据库后把新消息当成旧记录排除。即使设置有效起点，也保留最近 8 条消息用于连续接话；历史原文仍可检索。程序接口为 `ChatDatabase.set_context_cutoff(conversation_key, after_id)`，传入 0 可取消起点。

## 视频陪看和鲸鱼心跳

可以说“找个讲 GPT 的视频一起看看”，模型会搜索 B 站、读取画面并分享截图；也可以说“看看浏览器里这个视频”，从 Chrome、Edge 等浏览器可见窗口的当前标签地址读取 B 站视频。浏览器需已打开且没有最小化，多个窗口时优先采用读到的第一个视频标签。这里只能确认标签地址，不能确认播放器是否正在播放或当前播放秒数。读取不到会说明原因。最近视频会与会话一起保存，后续可继续讨论，无须反复贴链接。截图带视频时间点，点击可查看原图。

输入栏的“鲸鱼心跳”默认关闭，重启后保留开关和设置。v1.52 起先在后台结合持续打算、新见闻与近期聊天选择做事、聊天或休息；不会每次唤醒就截图点评。没有具体安排时参考间隔随机浮动，有打算时自己安排继续时间；新聊天和实际视频结果也可以引起注意。内部选择不产生聊天气泡。“现在找我聊聊”可手动发起话题。正在输入、聊天生成或等待真实回复时让位；可选锁屏/长时间未操作时继续后台工作。仅在软件运行时活动。

后台收到主动消息时，默认弹出系统通知、闪烁任务栏并播放提示音，按钮显示未读数量；点击通知或托盘图标可回到聊天。系统通知是否显示还取决于 Windows 的通知设置。互动设置可分别关闭提醒和声音。

互动设置中的“允许主动操作电脑”沿用输入栏“电脑操作”的开关与批准模式：电脑操作关闭时不会执行命令，逐次确认时等待你批准，自动批准时可直接执行。关闭鲸鱼心跳或更改互动设置会取消正在进行的主动任务，已经产生的操作记录会保留。聊天没有固定招呼、预告、总结和追问模板；可以先安静做事，遇到想说的新发现再发一两句。

内部选择使用文字资料，不自动上传截图。需要看桌面时由模型调用观察工具，仍需开启观察和电脑操作权限；截图在内存中使用，主动分享的画面保存为附件。屏幕观察需要视觉模型，其他模型仅能接收窗口文字。内部选择与执行都使用已配置的模型并计入用量。

软件统一显示为「鲸伴 · 有记忆的陪伴」，角色名称仍为大肥鱼。assets/jingban-icon.png 是图标原图，assets/jingban-icon.ico 是 Windows 多尺寸图标；构建启动器会将图标嵌入鲸伴.exe。


启动页为 760×450 的紧凑单页，使用大肥鱼二次元角色图与白色背景，突出事件版本追踪、消息来源映射与按需检索式上下文组装，启动完成后自动进入聊天。源码启动时如 launcher.ui 比 ui_launcher.py 更新，会自动重新生成界面；修改 Python 或 UI 后直接重开 start.bat，EXE 则需运行 build_launcher.bat 重打包。


历史问答加强：询问最早发言时，程序预查询当前会话原始消息，明确标记现存第一条；数字、单字、测试消息都计入，不受风格起点影响。指出遗漏或追问更早记录会重新预查。明确询问旧事时，除开头记录已有直接查询结果外，会要求模型在最终回答前调用历史或记忆工具核实；核实前的拟答暂不展示。此类问题可能增加模型请求和 Token 用量，无法保证模型每次理解均正确。

历史检索现区分原始表达与后续回忆问答：清理检索问句中的泛化词，对回忆问答降权，并沿显式引用关系回溯来源；保留真实后续更新的时间优先关系。图片问题直接查询带图片附件的原消息，结合上传时紧邻的首次回复作描述线索，不采用后续回忆讨论替代原图。证据已由本地预检索提供时不再强制模型重复查库；视觉模型可用 read_message 按需回读最多两张历史原图。


## 网页搜索、搜图和直接发图

本地聊天增加 search_web / read_webpage / search_web_images / send_image / draw_picture 工具。无需额外 API Key，网页搜索合并 Bing 和 DuckDuckGo 的公开结果，去重后按关键词相关性排序；搜图使用 Bing 主站与备用入口，无结果时尝试 Wikimedia Commons。站点策略和网络可能影响可用性；失败时返回明确错误，不伪造结果。read_webpage 支持正文分页，提取普通 HTML 文字、链接与图片，不执行网页 JavaScript，不读取登录页面。不能因此宣称能理解任意视频网站的完整视频。

可以说「查一下这个话题，给我来源」「找一张蓝鲸的图片发给我」「画一个简单的小鲸鱼」。简单绘图由当前聊天模型编写静态 SVG，本机渲染成 PNG，没有接照片级绘图 API，不额外收取绘图服务费，但仍有聊天模型 Token 用量。工具会将实际图片插入聊天，支持打开原图和图片来源，关闭后重开仍能查看。图片存放在 data/attachments/assistant_images，来源信息随消息 extras 保存。发送图片也支持项目目录内已有图片，可以接上电脑操作生成的图片。

联网下载限制为公开 HTTP/HTTPS 地址、逐跳校验重定向，图片最多 12 MiB 并验证解码与像素上限。简单绘图拒绝外部图片、脚本和资源引用；不运行模型返回的任意 Python 代码。每轮最多分享六张，按需将实际图片回传给视觉模型；搜索结果摘要或文件名不代表已看过图片。图片发送目前接入本机聊天窗口，QQ 图片发送未接入。


发图结果校验：搜图返回稳定 image_id 并按会话保存最近候选，后续可直接按编号发送。图片请求在最终文字显示前核对本轮实际 image 卡片数量；未执行却宣称已发送时，会要求调用对应图片工具。没有成功卡片不能归因于刷新，发送张数以工具回执为准。


## 当前视频识别与历史视频隔离（2026-10-23）

live_video.py 区分「看看当前 B 站在播什么」与「回忆上次的视频」。前者在 main.py 构造请求上下文时关闭历史视频注入，不加入旧对话内容和个人记忆；chat_tools.py 同时跳过旧消息候选、事件检索与最近视频缓存推荐。历史视频回忆保持原路径。

当前识别由程序先执行不带 URL 的 watch_video，重新读取可见浏览器地址栏，再取得对应视频抽样画面。失败、多个不同视频窗口或当前模型不支持视觉时，直接返回原因，不让模型用旧视频补全。成功回执含本轮 URL、标题和读取时间，才会进入模型；本轮限制可用工具，禁止用历史查询或 review_recent_video 替代当前观测。同一轮重读复用本轮回执，减少重复下载。

图片卡片明确标注「本轮浏览器标签读取 · 全片抽样画面，非当前播放位置」。这只能识别可见浏览器标签中的 B 站视频，不能判断实际播放/暂停状态、后台其他标签的媒体播放、播放秒数或音频。为避免读错，多窗口存在不同视频地址时要求明确目标，不默认挑第一个。

验证覆盖当前/历史意图区分、上下文隔离、缺少浏览器结果、多视频歧义、成功新标签与画面卡片、历史替代拒绝。使用模拟浏览器/视频/模型，不调用用户聊天 API。


## 本轮工具依据与真实性校验（2026-10-23）

新增 evidence_guard.py：统一记录工具名称、能力范围、来源时间、成功/失败/取消状态，以及不含网址查询参数的目标摘要。历史检索、搜索摘要、网页正文、历史视频、抽样画面、图片发送和电脑命令分开标记。消息上的「查看本轮工具依据」可查看本轮回执；回执随消息存入 SQLite，不保存完整命令或网页原文，也不作为下一轮当前状态的证明。

当前设备状态请求不注入旧回复和个人记忆；联网查询跳过个人历史候选与事件预检索，避免拿旧回答代替最新资料。当前桌面查询先沿电脑操作总开关读取本轮窗口和屏幕；标题与实际截图区别处理，非视觉模型不能据窗口标题猜屏幕画面。截图在GUI线程采集，只在内存中发送给聊天模型，不新增磁盘截图。普通聊天保持原有流式输出；涉及工具和当前状态的任务在完成声明展示前检查回执，缺少对应依据时核实一次，仍无依据则明确未核实。失败、超时、取消不算完成，取消电脑操作后本轮后续命令被拦截。

命令成功退出只表示执行器返回；还检查声明的操作种类是否有对应成功命令，以及当前进程/服务/指标声明是否有读取依据。不同目标是否完全匹配、任意脚本的真实效果和自然语言每一句事实，不能仅靠这些规则完全证明，仍需结合工具返回与实际状态。此机制减少无执行依据的操作声明，不等于消除所有模型幻觉。

本地模拟覆盖：普通闲聊、网络与历史来源区分、摘要与全文区分、无关命令成功、失败/取消、当前状态与资源指标、屏幕权限、引用/假设表达、回执保存与卡片显示。未调用真实模型API、未执行真实系统命令、未实际采集用户屏幕。

自制插件放在 plugins/my_plugin/，包含 plugin.json 和 main.py，也可以带 assets 等资源文件。点「开发说明 / 模板」查看完整接口，或生成可导入的开发模板。入口示例：

```json
{"id":"my_plugin","name":"我的插件","version":"1.0.0","api_version":1,"entry":"main.py","permissions":[]}
```

```python
class Plugin:
    def __init__(self, context):
        self.context = context
    def start(self):
        self.context.notify("插件已启动")
    def stop(self):
        pass

def create_plugin(context):
    return Plugin(context)
```

生命周期为 create_plugin(context) → start() → stop()。可选 show_settings()，由插件页「打开 / 设置」调用。停用时停止自己的线程、网络请求和计时器；不要阻塞界面线程。context.track() 托管窗口、计时器等 QObject，QThread 应在 stop() 自行取消并等待退出；context.on_cleanup() 可登记额外清理函数。

用户插件位于 plugins/，独立数据位于 plugin_data/<插件ID>/，启用状态位于 plugins.json；联网更新不覆盖这些用户文件。会话备份仍只负责聊天与记忆，迁移自制插件时请单独复制这三个位置。内置示例源码在 quick_phrases_plugin.py，SDK 在 plugin_sdk.py。旧原生桌宠的插件数据不自动清除，新示例默认停用。

## DSH 原版插件兼容（v1.33）

入口为左侧「插件」→「DSH 插件兼容」。导入含 package.json 的原版插件文件夹、ZIP 或 npm .tgz 发布包，查看入口、依赖和兼容范围后点击「启用」。页面使用整体纵向滚动，按钮按宽度排列，运行日志默认折叠。没有预置插件下载入口。原生 Python 插件仍在另一页管理。

### 可运行的原版入口

- 独立入口：识别发布包 package.json 的 bin 中唯一的 `standalone` 或 `*-standalone` 入口，直接执行原 JavaScript 文件。包含 DSH 客户端代码但另外提供独立入口的插件，使用其独立模式，保留原版窗口、交互和设置。
- Cordis 后台入口：运行原版 main / exports 入口，提供 Cordis 4.0.4 基础上下文、生命周期和事件。普通 npm 依赖在启用时准备，不再只接受无第三方依赖的插件。DSH 专属模型、会话、工具及页面服务仍需进一步适配，缺少的依赖或 inject 服务会明确报错。
- 只有 TypeScript 源码、缺少 JavaScript 产物的仓库包需要先构建。导入不执行源码构建或 Cordis YAML patch，也不将插件重写成 Python 插件。

### 依赖与运行管理

首次启用会自动从 nodejs.org 准备共享 Node.js / npm（校验官方 SHA-256），安装固定版本 Cordis 核心库（校验固定 SHA-512），然后按原包 dependencies 安装 npm 依赖。依赖在单独目录准备，原插件文件保持不变；npm 使用官方 registry、生成锁文件并校验包完整性，禁用生命周期脚本和开发依赖，不自动安装 DSH 的 peerDependencies。需要安装脚本的原生扩展可能无法直接使用，错误会出现在插件日志中。「准备 / 修复依赖」可重新准备当前插件的运行依赖。

插件运行在独立无控制台 Node 进程中，窗口由插件自身创建。Windows Job 在发送入口前接管进程树；停用或退出时先通知原插件清理，再结束仍未退出的所属进程。退出等待采用异步方式。插件仍具有当前用户系统权限，独立进程不是安全沙箱，只启用可信来源。

「启动设置」中，Cordis 入口填写插件自身 JSON 配置；独立入口使用 `{"arguments":[],"environment":{}}` 设置参数和环境变量，保存后下次启用生效。DSH_HOME 统一指向 data/dsh/state，避免读写用户其他 DSH 安装的数据。Node 的控制参数及此数据目录为保留设置。

### dsh-pet 原版插件

直接导入 dsh-pet 的原版发布包，使用其声明的 `dsh-pet-standalone` 入口，不改写插件文件，不抽取动画生成自制桌宠。动作、拖拽、物理和桌面窗口由原插件自己的 Electron Helper 实现；首次启动所需 Electron 由原插件按需下载，其进度和错误进入本页日志。

服务启动后可点「打开插件界面」进入原插件的本机设置页面，也可使用原版桌宠自己的菜单。独立模式的模型接口、聊天历史和主动碎碎念使用插件自身设置，不自动复制鲸伴密钥或接入鲸伴数据库；原插件独立模式不提供的 DSH 宿主会话、余额与系统通知不显示为已支持。由 v1.32 自制桌宠模式迁移时默认停用，用户确认启用后才运行原版代码；保留原包和旧设置。

启用原版 dsh-pet 后，默认将鲸伴本地聊天及鲸鱼心跳**新生成并保存的 AI 回复**通过原插件的本机气泡接口，显示到设为 desktop / both 的桌宠上。长回复每段最多 120 字，带页码依次展示；同步最多 8000 字，超长部分提示返回鲸伴查看。新一轮本地消息会停止旧回复翻页；打开历史不会重播。到「启动设置」关闭「同步鲸伴 AI 回复到桌宠气泡」，保存后立即生效。此功能只转发现成回复，不发送思考正文、QQ 消息或 API 密钥，不额外调用模型，也不写入原插件自己的聊天记忆。原插件独立的聊天、碎碎念仍使用其自身模型设置。关闭、停用和清空聊天时会取消待显示内容，清空聊天只收起桥接显示的气泡。

### 数据位置

原包、共享运行环境、插件依赖、状态和日志均在 data/dsh；联网更新不覆盖这些用户目录，纯净发行版和聊天备份不包含它们，恢复聊天备份保留本机插件状态。移除将插件移至 data/dsh/removed 并保留设置。

Cordis 入口可以在设置中选择开放本地聊天事件，默认关闭。事件为 `jingban/message`、`jingban/chat_state`、`jingban/voice_state`，正文最多 8000 字符，不含模型深度思考正文或鲸伴 API 配置；`jingban/data_cleared` 用于通知插件清理自行保存的数据。这些事件不替代 DSH 的专属会话协议。独立入口不接收通用事件注入；dsh-pet 的回复气泡使用上述专用桥接。

## QQ 账号与自主说说

在「QQ 接入」下方新增「QQ 账号与空间」，连接桥接后使用：

- **账号资料**：读取当前登录账号，修改昵称、个性签名、头像及在线状态。头像支持选择本地图片或粘贴 HTTP(S) 图片链接。只修改指定字段，单独改签名会保留当前昵称。
- **发布说说**：编辑正文、添加和移除最多 9 张图片，发布到 QQ 空间；可见范围在「自主与权限」中保存，支持所有人、好友、部分好友、仅自己及部分好友不可见。
- **聊天操作**：本地聊天可直接说“把 QQ 昵称改成……”或“发一条说说：……”。QQ 私聊也可执行，须将发指令的 QQ 号加入独立的**账号操作 QQ 白名单**并保存。普通自动回复白名单不自动获得账号操作权限。开启普通自动回复不是账号指令的前提；白名单中的账号指令会单独回复结果。私聊中的图片可在 15 分钟内用于该会话明确要求的头像或说说配图。
- **自主与权限**：保存“允许她自主发 QQ 空间说说”后，鲸伴运行且 QQ 桥接在线时会独立判断发布机会，不依赖鲸鱼心跳开关。默认最短间隔 180 分钟、每天最多 2 条、好友可见、23 点至次日 8 点安静。开始运行后随机等待约 3–5 分钟再首次检查，没有合适内容可跳过；修改参数后保存生效。
- **自主内容**：使用程序内置角色设定、当前时间、主题偏好和此前自主发布的内容，不读取私人聊天、记忆、屏幕或手动说说；自主模式目前只发文字，不主动改昵称或头像。生成使用现有模型接口，用量计入软件统计。
- **执行记录**：以桥接成功回执确认结果，发布成功保存说说 ID。掉线、超时或缺少说说 ID 记为结果不明，不自动重发；同账号 24 小时内相同内容防止重复发布，程序中断后的待确认记录保持为结果不明。QQ 的资料或内容审核可能晚于接口回执。

账号操作记录存于 `data/onebot/qq-account-actions.json`，包含实际操作账号和发布正文，不含 QQ 令牌或头像图片。联网更新和纯净发行版不包含这些记录；聊天备份 / 恢复与清空聊天保留本机 OneBot 运行状态和账号操作记录，避免恢复旧备份后重复发说说。纯净发行版默认关闭自主发说说，QQ 账号操作白名单为空。

## QQ 私聊扩展（v1.42）

- **自行搜图换头像**：账号操作白名单可以在 QQ 说“帮你自己找张白鲸头像换上”。AI 会联网搜图、选择真实结果并调用换头像接口，成功以实际桥接回执为准；也可继续使用你发来的图片。搜图、简单绘图和本地截图图片可直接通过图片工具发回当前 QQ。
- **QQ 电脑操作**：到「QQ 接入 → QQ 账号与空间 → 自主与权限」开启“允许账号白名单通过 QQ 私聊操作电脑”。该权限与本地聊天电脑操作分开配置，只对白名单私聊开放，可读取当前屏幕及调用现有电脑命令工具。
- **确认与停止**：不勾选自动执行时，QQ 会收到完整命令及确认码，回复“确认执行 XXXXXXXX”或“取消执行 XXXXXXXX”，确认两分钟内有效，仅发起者可确认。勾选自动执行后按当前任务直接执行；发“停止电脑操作”会取消本人的当前 QQ 任务及排队任务。关闭权限后待执行命令会取消，正在执行的命令会请求停止。已发生的修改不会自动撤销。
- **收藏表情**：开启自动收藏后，保存白名单用户发来的 QQ 表情图片，不自动收藏普通照片；普通图片可明确说“收藏这张表情”。按图片字节摘要去重，保留 GIF 动画，单张最多 10 MB，QQ 收藏部分最多 1000 张 / 200 MB。图片进入 `assets/stickers`，描述位于 `data/qq-stickers.json`；可在现有聊天表情管理中查看、删除。
- **按语境发收藏表情**：开启“允许 AI 自主发送表情包”后，AI 可查询本地表情库、选择已有文件发送；视觉模型可读取首帧再选，每条回复最多一张。图片发送等待 OneBot 回执，结果不明时不自动重发；图库不包含模型猜造的文件。
- **下次快速登录**：内置 OneBot 勾选“记住账号，下次快速登录”并保存；成功登录后记录实际账号，下次启动指定该账号复用 QQ 自己保存在本机的登录态，不保存 QQ 密码。旧版仅有一个账户配置时会迁移该账户；多个旧账户不自动猜选。快速登录未成功约 35 秒后切换二维码，也可手动刷新。QQ 登录态过期或要求手机验证时仍需重新扫码。

聊天备份保留收藏表情，纯净发行版不包含用户表情、白名单及登录状态。新用户默认关闭 QQ 电脑操作和自动收藏；账号操作白名单仍单独维护。更新保留已有设置和本机数据。


## QQ 图片与 B站漫游（v1.43）

- QQ 发来的图片会在后台下载、校验并保存为原消息附件，再以真实图片数据送给视觉模型；不再只提供临时网址。下载失败会通过桥接 get_image 再取一次，本机桥接可读取其回执指定的图片缓存；不直接信任消息里的本地路径。动态图理解仅首帧，原始表情收藏仍保留动画。
- 图片理解需在设置选择 **deepseek-flash**。截图、网页文字均作为资料，不能授权账号或电脑操作。QQ 普通搜索和发图由既有自动回复/账号操作白名单限制；读取当前浏览器还需电脑操作权限。
- 打开 **QQ 接入 → QQ 账号与空间 → B站漫游**，设置是否开启、是否打开浏览器、连续闲置时间、轮次间隔、每日上限及主题，然后保存。软件需保持运行，后台按主题自行搜索，不需要每次给链接。
- 标准参数：键鼠及 QQ 均闲置5分钟后开始，每30分钟最多一轮，每天6轮，失败和取消也计数。每轮最多分析一段、最多尝试两个候选，每段不超过10分钟/100MiB，取最多6张真实画面，不读声音。恢复键鼠输入或发来QQ消息后取消当前任务；正在等待的网络请求可能需要等待超时才能结束。
- 此页显示来源链接、观看札记及最新真实截图；在本机或授权 QQ 中可问“你刚才刷了什么视频？”，AI 使用 read_bilibili_visits 读取真实记录。记录不是当前浏览器状态，也不证明完整看完。浏览器打开页面不能保证站点自动播放。
- 公共视频解析受站点/网络/登录要求影响，失败保留原因；不会绕过验证码。每轮视觉理解产生正常模型用量，可在此关闭、降低频率或减少每日上限。
- 浏览记录在 data/bilibili-visits.json，截图在 data/attachments/video_cache；联网更新保留，纯净发行版排除，清空全部聊天时一并清理。新用户默认关闭漫游，本次按需求为当前电脑开启。


## 连续B站漫游与QQ分条回复（v1.44）

1. 在 **QQ接入 → B站漫游** 开启“独立浏览器窗口实际播放”，设置一轮连看数量、每段最长播放时间及主题。默认一轮3段、每段最多120秒、两轮间隔30分钟、每天最多12段；日上限包含失败和取消。短视频到结尾即换片，长视频到上限后换片，不等于完整看完。
2. 点击 **现在开始一轮** 可立即开始；程序会在自己的漫游窗口播放、采样、生成感想、分享并换下一段。定时漫游需键鼠和QQ均闲置达到设置时间；v1.46起默认允许边聊天、操作键鼠边继续浏览，明确停止仍会取消本轮。
3. 播放控制使用电脑已有Edge或Chrome以及独立用户目录 **data/bilibili-browser**，管理一个专属标签。仅操作漫游标签；按播放器实际进度取图，默认静音，没有声音理解。浏览器搜索和当前视频推荐可作为下一个视频来源，不循环打开同一条；播放卡住时尝试下一候选。登录或验证提示会终止本轮，不自动绕过。
4. 需要B站登录时，点击 **打开漫游登录窗口** 在该窗口手动登录，再点击开始。登录信息与平时浏览器分开，保存在本机，下次可复用；程序更新不会覆盖，也不会打入聊天迁移包或纯净版。
5. 勾选 **看后发到软件聊天** 会主动插入实际感想和截图，按原通知设置提醒；不依赖鲸鱼心跳开关。勾选 **主动发到QQ** 时填写接收方，须在账号操作或自动回复白名单内，并保持QQ桥接连接。每段观看后发送链接、实际截图及短感想，记录中显示发送结果。发送结果不明时需在QQ核对，不自动重发。
6. QQ普通文字回复会按自然段分成几条气泡，长段落继续按句子拆分，保留链接和代码块，逐条等待回执并间隔发送。界面与数据库保留一条完整逻辑回复；分条发送不额外调用模型。命令确认消息保留原格式。
7. 关闭实际播放时仍可用视频文件抽帧模式；该模式只分析抽样图片，不宣称浏览器已播放。每次视觉感想会产生正常模型用量。启用“恢复键鼠时暂停”时，恢复活动会取消未完成的观看与生成；默认关闭。已经开始发送的分享可继续完成，点击停止本轮可取消剩余发送。


## 在QQ中真正启动B站漫游（v1.45修复）

此前“去刷会B站”可能仅得到模型口头答应，实际没有启动任务；读旧札记也不会产生新观看。本版将聊天指令直接接到实际调度器：

- **去刷会B站吧**：当前回复结束后启动一轮，仍按设置的数量、时长与每日上限执行。
- **去刷我的B站收藏**：打开独立漫游浏览器，从其中实际登录的账号读取收藏；它与平时浏览器分开，需要先在漫游窗口登录。未登录、验证或收藏读取失败会报原因，不转为普通搜索。
- **你逛到好看的了吗 / B站漫游进度怎么样**：读取真实任务状态及本轮新增记录数量，旧记录不冒充新任务。
- **停止漫游**：取消排队、当前漫游及剩余分享；已发消息或已完成操作不会撤回。

“已安排”只表示排队；浏览器尚未打开时会明确说明。v1.46起默认只分享有内容的感想和实际失败原因，不逐轮播报开始和结束；可另开开始提醒。已开始的任务默认不会因闲聊或键鼠恢复取消，明确停止、功能关闭或权限撤销仍会暂停。自动开始仍遵循闲置规则。

QQ控制限账号操作白名单，启动还需QQ电脑操作权限；开关关闭、模型配置不满足、日限额已用完时不会启动。任务状态保存在 data/bilibili-session.json，札记携带独立 task_id，更新保留个人状态，清空聊天时一并清除。更新程序后需完全关闭并重新打开软件，已在运行的Python进程不会自动替换内存中的旧逻辑。


## 自然接话、边聊边看和跳看（v1.46）

- 对话正在谈B站浏览时，“好吧，你自己去看吧”“继续吧”可直接承接，不要求固定口令；模型也能在已启用的B站漫游权限内选择启动。开启离开时自主浏览后，达到闲置时间也会自行开始，无须每轮发命令；仍受每日次数和轮次间隔约束。
- QQ接入 → B站漫游新增“恢复键鼠操作时暂停”，默认关闭；正在浏览时普通聊天与移动鼠标不取消，换片不会反复把浏览器抢到前台。要停止可说“别看了”，要换片可说“换一个”。
- “按兴趣跳看”默认开启：先读取约6秒后的真实开头画面，最多增加一次短视觉判断，再继续看、跳到中后段或换下一条。每条最多两次跳转，记录实际确认位置和所看片段；单片停留上限仍有效，短视频可能正常看到结尾。关闭后沿用结尾或上限换片。
- 每条跳看最多增加一次模型判断，视觉感想仍单独请求；不按每帧调用模型。用量一并记入autonomous_video。播放器静音，只讨论真实截到的画面，不编造声音、台词或跳过的剧情。
- 默认关闭QQ开始提醒，普通结束和取消不再逐项汇报；有内容时先聊感想、发截图，再附来源链接。失败仍说明原因，机器任务状态与分段进度保存在浏览记录内。更新后需完全退出并重新打开软件。


## 客户端与本人QQ跨端同步（v1.47）

1. 完全退出并重新打开鲸伴，在 **QQ接入 → 跨端同步** 填写本人QQ号并保存。留空可解除绑定；本版默认留空，更新不会自动绑定白名单中的账号。绑定仅共享身份上下文，自动回复、账号操作及电脑操作权限仍由原开关和白名单管理。
2. 绑定后，客户端与该QQ合并读取最近24条消息，消息保留渠道和时间；历史原文、上传图片、事件、最近视频和有来源的长期记忆按绑定范围检索。已有记录无需迁移或复制；其他QQ保持各自会话，未注明消息来源的手工长期记忆留给本机使用。
3. 每轮共享少量真实任务回执，较早任务可由AI调用read_task_records按关键词查找。命令退出、文件核对、工具返回分别保存；退出码0不代表目标应用或定时任务已经完成。询问当前状态需要实时检查，旧指令不是重新执行的授权。
4. 可另勾选 **客户端工具任务有结果时，通知本人QQ**。仅向当前绑定账号转发本地工具任务的原回复及可用结果图片；普通闲聊与其他QQ对话不自动转发。不增加一次模型生成，原文字按自然段发送，等待QQ桥接回执。
5. 通知保存在聊天数据库的owner_notifications表；同一回复和接收方最多排队一次。断开桥接时保留待发，超过24小时作废；已发送、失败和结果不明都不自动重发。导入备份不恢复发送旧待发通知。设置页显示待发、已确认、未确认/失败数量。
6. 解除或更换绑定只改变之后的读取范围，不改写物理消息、不撤回QQ消息。聊天或通知正在运行时先等其结束再改绑定；删除和清空聊天会同步清理通知记录。个人绑定在config.json，联网更新保留，纯净发行版默认不绑定。

此功能在同一台运行鲸伴的电脑上使用本地数据库，不需要额外服务器；软件和QQ桥接须运行，QQ本身未收到的历史客户端聊天不会自动全部补发。


## QQ统一工作区与主动互动（v1.48）

- **连接登录**：启动内置QQ，扫码和登录状态在这里查看。路径、管理端口与日志收在“高级路径与运行日志”；外部OneBot连接配置单独展开。
- **信任与权限**：只维护一份QQ号名单，逗号或空格分隔。旧回复/账号名单在首次升级时合并，之后以这份名单为准，兼容字段account_allowlist自动镜像，不再独立编辑。自动回复、表情、语音、账号操作、电脑操作按各自开关启用；部分好友可见/不可见的空间发布范围也使用此名单。添加联系人意味着它可以使用已启用的账号及电脑功能。
- **主动互动**：可开启QQ桥接在线时主动联系信任名单中的人；默认每人间隔60分钟、每天最多4次尝试，避开刚收到私聊的5分钟和原有安静时段。每次选择一人，不批量群发。程序启动后有短暂等待，聊天生成进行时不启动新一轮。可选“仅确认对方在线时”模式；无法确认或忙碌/免打扰时跳过，不根据在线状态猜对方活动。
- **查看动态**：开启读取权限后，选择联系人点“查看最近动态”，也可在私聊让AI查看可见空间动态。通过桥接get_cookies取得现有QQ会话，在内存中请求QQ空间feeds3，只保留目标联系人的文字条目。不会额外安装浏览器或完整SDK，不读取或发送Cookie给模型，不自动点赞、评论。
- 当前读取近期一页，**不是完整空间历史，也没有配图/视频视觉理解**。没有解析到内容时会说明未读到，不断言对方没有发动态。登录失效、验证、访问权限或页面格式变化可能导致读取失败；不绕过限制。接口与来源依据见[NapCat官方API](https://napneko.github.io/onebot/api)及[feeds3实现维护文档](https://github.com/Gu-Heping/onebot-qzone/blob/main/doc/feeds3-parser.md)。
- 主动消息参考该联系人的近期上下文、角色设定和实际读到的动态；本人绑定仍是独立选择，未绑定时不读取客户端的私人对话。旧任务不重新执行，旧动态不当成刚发生的新事，没有新话题可以不发。
- 实际生成消耗聊天模型用量；纯读取动态不调用模型。消息按自然段等待桥接回执后发送，失败或结果不明不自动重发。SQLite表qq_proactive记录尝试、草稿、发送状态及动态来源，QQ接入“运行记录”可查看；清空聊天会清理，备份导入不重放。
- 手动体验按钮只执行本次点击；自动模式独立开关。纯净发行默认关闭主动聊天和空间读取；本次根据需求为开发电脑开启，保留原安静时段。全部设置使用页底“保存全部QQ设置”。

DSH管理页只在导入报告或展示配置改变时重建卡片。启用、停止、就绪、错误原位更新，保留按钮布局和预留滚动条宽度；插件自己的独立界面仍由插件代码决定。

## 自主行为与持续打算（v1.50）

聊天栏“鲸鱼心跳”面板可开启“允许自己选事做并保留打算”。没有每日自主次数、每轮总时长或工具调用次数配额。她可以连续使用工具推进自己的事情，自己决定继续、换个打算、等一件事或休息；通过 update_self_state 的 resume_after_minutes 和 resume_reason 保存何时继续及原因，0 表示尽快接着做。安排保存在数据库，重启后仍按自己的打算继续。设置面板的参考间隔只用于没有具体安排的情况，不覆盖她自己保存的时间。过期的继续安排在开始时消费，避免旧时间使空闲检查不断重复。长时间未操作或锁屏时可选继续后台工作，锁屏不进行桌面输入。

主动操作仍需聊天栏“电脑操作”开启；自动批准时按当前 Windows 账号权限执行，逐次确认时显示操作确认。既有角色卡和自定义人格保持，增加独立偏好与打算的表达。角色兴趣、心情与目标是模型维护的角色状态，不代表真实意识，也不代表目标已经完成。完成打算至少需要本轮执行工具回执；回执只说明具体工具返回，不保证任意目标都达到。

“鲸鱼心跳”右侧菜单可查看打算与真实活动、暂停自主活动。进行中可以在本地直接发送消息，她会中断当前自主活动，待线程结束后接着处理消息。网络响应阻塞时可能需要等待当前请求超时，但中断后不再发起电脑动作。普通鼠标移动不会取消该活动；界面变化时具体桌面动作会要求重新观察。新作品默认放在 data/agency/workspace，动作过程仍可在聊天记录的工具依据中查看。

SQLite 增加 agency_state、agency_journal；安静活动的回执使用隐藏内部记录保存，可通过“历史记录”筛选隐藏记录查看操作详情。内部记录不作为普通聊天消息或长期记忆提取素材，避免机械日志影响上下文；回顾时可使用 read_self_state/read_task_records 查依据。已绑定的本人 QQ 可以读取同一份状态；未绑定的其他 QQ 不分享本地打算和活动上下文。QQ 主动聊天、B站分享使用一致的有主见表达，发送权限仍沿用各自设置。

“清空所有”会清理自主角色状态和活动日志，保留手动偏好与创作文件。备份导入保留历史回执，将未完成活动标记中断，不自动重放操作。纯净发行默认不开启自主活动或电脑操作。手机控制尚未加入。


### 自主节奏（v1.50）

自主状态现在保留 resume_at、resume_reason、plan_revision；模型可以按兴趣、实际进展和用户情况调整打算，不必按固定次数结束。有下一步的进行中打算会优先继续；用户临时聊天会让出当前执行，后续仍可继续未完成打算。没有新进展时可以安静做事、休息或等结果，不强制编一个新话题。网络失败采用重试退避，单次网络请求和命令的故障超时保留，不将它们当作整项活动的总时长限制。

B站、QQ主动搭话和自主说说的旧每日默认限额迁移为0，表示不按每日次数停下；设置页可自行选用正数限额。原有安静时段、发送权限、联系人范围和各自互动间隔保持为用户偏好，不会因取消日限额而强行给联系人不断发消息。自己选择休息时间和普通聊天的实际表现仍由模型决定，这些机制不代表真实人类意识。

## 即时聊天与真实等待（v1.51）

日常对话默认简短自然，用户要解释、代码、教程或报告时充分展开，不通过裁切正文或固定拆成三条模拟聊天。具备电脑操作或鲸鱼心跳权限的聊天回合新增 chat_message：模型可以在操作中现在就发一条消息，随后实际调用工具，看到新东西再接着聊；最终没有新的内容可用内部标记 [[sent]] 结束，界面不会显示该标记或自动补一段总结。普通未开启操作的聊天也使用简短接话风格。

chat_message 的 wait_for_reply=true 表示后续需要用户回应：发出当前问题后立即结束本轮执行，在 SQLite interaction_waits 保留问题、目标与下一步，鲸鱼心跳不会在等待期间继续该本地打算；QQ自动搭话也不会在等待期间给该联系人另发一轮话题。真实用户新消息恢复对应提问上下文，不把“可以”当成另一个旧任务的口令或付款下单的具体授权。明确拒绝会阻止原打算继续，改变话题时由模型根据用户的新意愿处理。等待跨重启保留；删除、清空或重新生成提问时清理，不自动把被删的问题当授权。

share_screen=true 可分享最近 observe_desktop 的实际截图，可选 crop={x,y,width,height} 截取截图像素区域。没有新截图、观察权限已撤销、桌面不可用或窗口改变时不会发图。图像保存在 data/attachments，并作为真实图片消息记录；本地和QQ使用同一张截图，QQ等待桥接真实回执。QQ发送前记录消息和等待问题，避免快速回复早于发送回执时错位；结果不明不重放，重启后未确认发送显示未知。

过程消息各自有实际时间、来源与工具依据；空过程标记不显示成气泡。进行中可以插话并中断当前动作，本地开启的语音会将过程短句分别关联到对应消息。保持用户自定义角色设定，不加入固定购物台词或模拟双方聊天脚本。具体措辞、主动性和是否选择分阶段交流仍取决于模型输出；本版本只做了源代码语法检查，尚未进行模型、QQ和桌面操作的实机联调。

## 鲸鱼心跳重做（v1.52）

采用“注意到新情况 → 内部选择 → 实际执行 → 留下经历 → 决定是否分享”的流程。内部选择只能输出结构化打算，不具有电脑操作和发消息的能力；选择做事后进入现有完整工具回合，继续沿用真实回执、即时消息和等待回复机制。定时器只是唤醒入口；具体选择由模型依据角色、连续打算和新来源判断，没有增加每日活动配额。

- **不再自动看屏幕找话说**：内部选择不上传截图；有需要才主动观察。允许研究、搜索、创作、使用应用，也可以安静或休息。当前窗口与输入时间只作为快照，不当成用户情绪或去向的证据。
- **记住自己的事情**：`keep_intention` 维护多个持续打算和未完想法，可接着做、暂放、完成或放下。`update_self_state` 与同一份打算同步，保存下一步和继续时间。重启后保留打算，重新判断，不直接重放旧命令。
- **真实见闻与聊天分开**：`remember_discovery` 需要本轮实际工具来源，保存读到的内容与自己的理解，不能无来源写虚构经历。`read_companion_life` 回顾打算和见闻；过去的回执只支持过去的经历，不能证明当前屏幕或本轮执行。
- **看视频不等于必须分享**：鲸鱼心跳与自主选事开启时，由内部选择决定何时启动 B 站，不再同时由独立闲置定时器另起活动。自己启动的视频结果先成为见闻，再决定是否分享。`chat_message(video_id=...,text=...)` 可以附真实观看截图，沿用本地分享开关。已开启的QQ视频分享保留：视觉回合根据本次实际画面单独选择是否分享，仍只发给配置的接收方并保存桥接回执；不会把本地私人聊天发给其他QQ。未绑定QQ不能通过聊天工具读取本地自主见闻。用户明确发起的漫游仍沿用原分享设置。
- **查看她在惦记什么**：鲸鱼心跳面板新增当前情况入口；活动面板分为此刻与打算、新发现与未完想法、实际行动依据。内部选择的理由也可查看，休息不会伪装成对话消息。
- **新消息优先**：内部决策期间收到新消息、改变权限或本人绑定时，不执行过期选择。用户输入或等待回复时不另起自主对话；移动鼠标不等于取消活动。后台模型请求在阻塞时可能需要等网络超时才能释放线程。
- **数据与用量**：新增 `companion_meta/events/intentions/decisions` 表，随数据库备份保留，清空全部数据时一并清理；纯净发行不带私人打算和见闻。内部选择用量归入 `companion_decision`，真正执行仍归入原主动回合用量。未新增运行依赖。

参考了作者公开的 [DSH 心跳机制](https://github.com/Kanadego/dsh-heartbeat)与[自主刷 B 站演示](https://www.bilibili.com/video/BV1EPnG6DEJC/)及其[开源说明](https://github.com/Alterssss/dsh-bili-whale)。这是鲸伴自己的实现，没有装入这些插件，也未复制其每日次数限制。实际主动性、选题和措辞仍取决于当前模型；本次仅检查源代码语法，未进行真实 API、QQ、播放器或桌面操作联调。


## 鲸鱼心跳工作区（v1.53）

原“随心互动”现更名为“鲸鱼心跳”。重启后，左侧主导航或聊天栏同名按钮打开同一工作区；旧开关、兴趣、记录和权限直接沿用，不需要重新配置。

- **总览**：查看当前状态、打算、下一步、预计唤醒及已记录用量；可开启/暂停心跳、唤醒一次，或让她现在找你聊聊。唤醒仍会给当前对话和等待回复让位。
- **心跳机制**：展示留意新情况、形成选择、实际行动、留下见闻、决定分享的流程，标示当前实际决策/执行阶段。
- **兴趣范围**：保存你给的方向，查看她持续留下的兴趣和心情；编辑后单独保存。
- **心事匣**：保存留给下一次心跳的想法，可手动编辑和清空。手动便签注明用户来源；想法不冒充实际经历。

- **打算账本**：查看待续、完成和放下的打算；可以继续考虑、暂放或放下。手动暂停标记跨重启保留，不能由下一次自主选择直接恢复同一打算；“继续考虑”会解除该标记并重新判断。
- **节律与权限**：自主行为、观察、电脑操作、参考间隔及提醒分区管理。电脑总开关和批准方式仍在聊天栏；心跳不增加每日次数或总时长额度。
- **运行记录**：查看最近的内部选择及实际行动，含休息来由、失败/中断状态和具体工具回执；完整过程仍可从历史记录查看。

页面为主窗口内的非模态工作区，浏览时心跳可以继续；编辑字段时先让位。定时刷新不覆盖未保存草稿，也不触发模型请求。主导航和长内容支持滚动，标签较多时使用左右滚动箭头。清空全部数据时清理旧便签和记录显示；纯净发行包含新模块与图标，不带私人资料。

分区参考作者公开的 [DSH心跳插件界面说明](https://github.com/Kanadego/dsh-heartbeat)，展示和操作接入鲸伴现有机制；未装入DSH插件。本次仅完成源代码语法检查，未启动真实界面进行布局或模型操作联调。

## 结合聊天选片与自然分享（v1.55）

视频请求会保留当前原话及同身份的近期聊天。最新指定的题材、排除项优先于“选题偏好”；本人QQ只有明确绑定后才读取客户端的兴趣状态，其他QQ只参考自身对话。配置中的类别是软偏好，不再随机抽一串当搜索词。

每轮先由模型选具体方向及搜索角度，再筛选真实候选的标题、作者、时长和简介；关联推荐也须重新筛选。没有具体目标时可先逛B站首页；未登录时不保证个性化推荐。候选偏题可换词重搜，最多尝试三个不同查询，失败会结束本次选片，不默认播放第一条。收藏夹请求仍只在收藏内容中挑选。

选题计划、候选筛选理由和实际查询保存在本机 `data/bilibili-visits.json`；不写入私人聊天快照。选题规划每轮复用，候选筛选按实际需要调用模型，新增用量计入视频使用统计。此版完成源码语法检查，未进行真实QQ、浏览器和模型联调。

在 **QQ接入 → B站浏览** 选择浏览器：

- **独立窗口**：保留原来的 `data/bilibili-browser` 登录资料。日常浏览器中的登录不会自动带过来，需要在独立窗口登录一次。
- **日常浏览器**：点“准备日常浏览器连接扩展 / 安装说明”，在已经登录B站的同一个 Edge/Chrome 个人资料中打开 `edge://extensions` 或 `chrome://extensions`，开启开发者模式，选择“加载解压缩的扩展”，加载刚打开的 `data/browser-extension` 文件夹。然后选择“日常浏览器（扩展连接）”并保存。保持该浏览器打开，页面显示已连接后再打开或开始浏览。首次安装后会自动重连，也可以点扩展图标重连；换电脑需重新配对安装。

扩展使用 [Chrome debugger API](https://developer.chrome.com/docs/extensions/reference/api/debugger) 操作鲸伴自己创建的B站标签页，浏览器会显示调试提示条。不会把普通标签页全部接管，不复制或导出登录Cookie。扩展通过仅监听本机的随机配对连接通信；配对目录是私人资料，不进入纯净发行或网站更新包。未连接时会明确提示，不悄悄另开未登录窗口。新版Chrome对默认资料目录的远程调试有限制，相关设计见 [Chrome说明](https://developer.chrome.com/blog/remote-debugging-port)。

开启“允许她在已登录的B站页面发评论、点赞 / 取消点赞”后，可以在聊天中让她查看已加载评论、针对当前视频评论或点赞。电脑操作开关、QQ信任名单和批准方式仍生效。评论从网页实际输入框发布，需要读到带新ID的评论结果才确认成功；超时、验证、结果不明不会重复发布相同内容，操作记录在 `data/bilibili-actions.json`。页面结构变化或评论框未展开时可能无法定位，会明确失败。没有接入投币、关注、付费或验证码处理。

“视频停在那里不动”等反馈会优先核查实际播放器，可用“继续播放”“暂停当前视频”控制。播放判断使用真实进度及暂停标记；正常生成感想和选下一条时保持播放，取消、结束或失败时才收尾暂停。恢复播放会检查进度是否继续；原生播放被拒绝时只尝试点击播放器的播放按钮。手动接管后，旧模型任务的退出不会再把新恢复的播放暂停。

对话修复了将普通状态反馈误当成操作完成声明、纠正后仍沿用旧拦截原因的问题。内部审查理由留在工具记录中，聊天不再拼接“没有成功命令回执，不能宣称完成”等技术文案。普通表达继续沿用角色设定，并优先回应眼前问题。

已完成Python与内嵌JavaScript语法检查，未启动真实浏览器或QQ联调，也未登录账号、发布评论或点赞。实际登录、扩展加载与B站页面适配仍需要使用时验证。


## 设置、空间图文互动和插件网页（v1.57）

普通/工作模式改在聊天输入框上方切换。可以在对话里说“把深度思考关掉”“语速调为20”“改用工作模式”“查一下API余额”。AI 使用设置工具实际保存偏好，结果会同步到对应界面；思考从下一次请求生效。可管理的普通设置还包括后台通知、空闲心跳间隔、兴趣提示、视频跳看/选题和动态选题/间隔。软件连接密钥、信任名单、权限开关不交给模型自动修改。QQ 私聊中的设置管理沿用信任名单与电脑操作权限；API余额查询只适用于当前配置为官方 HTTPS DeepSeek 的连接，第三方中转余额无法按官方接口查询。

**QQ 接入 → 发布说说** 中有“自主动态可选配图”和“自主回复本人说说下信任联系人的一级评论”两个新开关，初始关闭，开启后保存QQ设置。自主发动态仍使用原来的独立开关、发布间隔、可见范围和安静时段。

配图来自最近实际播放的公开视频片段截图或实际搜到并下载的公开图片。模型根据真实图片决定是否选用和怎样表达；没有合适图片可以只发文字，无话可说可以跳过。自主生成不读取私人对话、记忆、整个桌面截图，也不会把搜来的图说成自己绘画或亲身外出。配图和正文经现有 QQ 桥接一起提交，以实际说说ID确认。生成和图像理解会产生模型正常用量。

空间读取和评论提交参考当前 [onebot-qzone 的 feeds3 实现说明](https://github.com/Gu-Heping/onebot-qzone/blob/main/doc/feeds3-parser.md)。这是网页协议适配，实际成功还取决于当前账号空间权限与页面结构；没有为了开发验证而对真实账号发动态或评论。

## 开机启动与托盘（v1.58）

在 **设置** 勾选“开机自动启动鲸伴，直接驻留托盘”，立即生效，不需要再点保存；取消即可关闭当前目录的开机启动。该项使用 Windows 当前用户的 [Run 登录启动项](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys)，不要求管理员权限，Windows可能按自身策略延迟启动。

登录后通过项目自带的无控制台 Python 运行 `app_startup.py --autostart`，整理本目录运行环境并静默启动聊天程序。不显示启动器、聊天界面或控制台，也不在登录时联网检查更新；手动打开启动器仍按原逻辑检查更新。心跳、QQ桥接、自动回复等沿用你已经保存的设置，不会因为开机启动而自行开启。

- 点击托盘图标或右键“打开聊天”恢复界面；心跳或通知关闭时托盘图标仍保留。
- 开机驻留或手动选择“收起到托盘”后，点窗口关闭会收回托盘。右键托盘选“退出鲸伴”才结束后台服务。普通手动打开、未收起到托盘的会话仍保留原来的关闭退出方式。
- 同一目录再次启动会唤醒原窗口，自动启动的重复请求保持静默。DSH网页插件在主窗口收起时不会自行弹出，可在插件页打开。
- 启动项是本机状态，不写入可分发的配置；纯净软件不会替别人开启。移动目录后请在新目录重新勾选；系统任务管理器若禁用了该启动项，需在系统中恢复启用。
- 诊断日志位于 `.updates/diagnostics/autostart.log`、`autostart-chat.log` 和 `chat.log`。启动失败或上次更新未完成时保持静默，可手动打开启动器修复。

本版完成源码语法检查，没有为验证而重启、注销Windows或启动真实QQ/插件。
